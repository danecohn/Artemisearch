# Optional AI overview and follow-ups

AI is **off by default**. On a results page, enable it, choose OpenAI or Anthropic, enter a model ID and your own API key, and press Generate overview. No API call happens merely by loading a search or turning on the panel. The user's provider account pays for usage; Artemisearch does not bundle credits or a ChatGPT/Claude subscription. Model defaults are editable and account availability varies.

The key, question, up to eight displayed result titles/URLs/snippets, and up to six recent conversation turns pass over HTTPS through the same-origin Artemisearch server to the selected provider's **fixed official endpoint**. The server uses the key only for that request and never writes it to a database, account settings, cookies, URL, or application logs. The browser holds it only in this page's memory. Turning AI off or closing/reloading/navigating away clears the UI's key and conversation. Nothing is stored in Web Storage. Infrastructure crash dumps/browser memory and provider retention are outside this promise; this is not a zero-retention certification. OpenAI requests set `store:false`, which disables Responses storage but does not override all provider abuse-monitoring policies. Anthropic retention follows its account policies. Users should set provider-side spending limits.

Results/snippets and conversations are treated as untrusted text. The prompt requires source-number citations, uncertainty, and no claims of reading full pages. Answers render as text, never executable HTML. Citation numbers are checked against the supplied list; invalid numbers are marked unsupported. Valid citation numbers do **not** establish that a source supports a generated claim. Readers must verify the source. The AI does not fetch arbitrary URLs, browse, execute tools, or take actions. It can make mistakes and omit context. The model may not follow every instruction.

API calls are bounded (32 KiB request, eight snippets, 1,600 output-token cap, 25-second network timeout, 512 KiB response cap). Keys are accepted only on a same-origin JSON POST. Redirects are not followed with provider credentials. Errors are sanitized so provider bodies/keys are not reflected. Search works normally when AI is off or unavailable.

Mocked transport tests cover both real wire formats, credentials redaction, fixed endpoints, citation bounds, and OpenAI `store:false`. No production API key is used by CI. End-to-end paid provider generation requires a user's own valid key; it is not claimed as verified without one.

Official references: https://developers.openai.com/api/docs/guides/text and https://developers.openai.com/api/reference/resources/responses/methods/create ; https://platform.claude.com/docs/en/api/messages/create .
